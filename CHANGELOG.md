# Changelog

## Unreleased

- `verify.py run mutation` works under `workflow: repo`: the one level that runs there, since the repository's own checks are the gate and write no receipt, so a clean tree replaces the passing `fast` or `full` receipt. The contract may then carry `verify.mutation` alone (`verify.full` stays required under the pothos workflow, now checked by `contract.py` instead of the schema), and the session context tells a repo-workflow session once that the level exists and when to run it. Every other level, and `check`, still exit 3 there. The base of a branch (for `mutation` and the `ui` check) is now the newer of the local base branch and its `origin/` copy: a worktree whose local `main` sits behind the remote counted every file landed since as changed.
- `update-dependencies` skill: updates npm dependencies only with an evidenced driver (`security` > `eol` > `drift-exposed` > `unblocks` > `bug`/`feature` > `drift-safe`), targets the newest version that has matured (`deps.cooling_off_days`, default 14; the window retargets, never cancels; a security driver takes the minimum patched version now), treats an installed major line with no release in `deps.dead_line_months` (12) as dead and therefore `drift-exposed`, applies every candidate at once in a worktree and lets the measured diff decide the pull request's shape: one mechanical pull request for what stays green and lockfile-only (runtime advisories in their own, ahead of hygiene), one pull request per migration up to `deps.review_budget` (3), a tracker ticket for what does not reach green, and a red security pull request as a draft marked for a person, never ready. `scripts/deps.py` does the deterministic part with the standard library: the inventory of every direct dependency (root and workspaces, installed versions from `node_modules`), registry dates and deprecations through `npm view`, advisories through `npm audit` or `pnpm audit` (both formats), peer ranges verified before a hold blocks a coupled package (`^18 || ^19` is not blocked by a React 18 hold) and against what the run will leave installed (a conflict fails the entry, never a blind resolution), the anchored import radius with configured tooling counted as wide and the test files to run first, holds and decisions from the repository file `deps.policy` names, reconciliation with open pull requests through `Dependency-Root`/`Dependency-Target` footer lines (same target: skip; older: supersede after the new one exists; a person's: never touched), a lockfile out of sync with `package.json` stopping the run, a lock so two runs never overlap, and the run record at `$POTHOS_HOME/deps/<host>/<owner>/<repo>/<date>.json` (`latest` next to it) with every external fact's provenance, the environment and an explicit failure for any package whose data is missing. `audit` mode does everything except publish; publishing confirms with the person and never merges. Contract: optional `deps` section (`exclude`, `cooling_off_days`, `dead_line_months`, `review_budget`, `label`, `policy`, `gates` per package-name pattern); `plant` reports `dependency_bots` (Renovate, Dependabot) and a policy file and maps the section; the session context adds one `Dependencies` line only where the contract sets `deps`. Five evals (`deps-*`) run against stand-ins for `npm` and `gh` with `node_modules` written by the seed and grade the run record and the logged calls: a red security advisory opens a draft for a person, the window retargets to the matured version, a peer range decides what a hold blocks, `audit` leaves no side effect, and a failed attempt never touches the original branch. Still open: the type-check as the detector of a removed API, visual evidence for UI packages, other ecosystems (`docs/roadmap.md`, phase 7).
- The merge guard reads the messages a person types while the agent is busy. The terminal queues them (`queue-operation` entries in the transcript) and hands them to the agent inside a tool result, which the guard skips on purpose, so a `--quote` of those words was refused and the person had to repeat the request in a message of its own. The queued text now counts as typed; the copy inside the tool result still does not.
- `component-design`: before writing, look for what already exists (a component with the same role, shared hooks, tokens, icons; the session context names the folders when the contract has `ui`) and reuse or extend it, with an additive change to a shared primitive in the same change; a decision row on when a piece becomes a file of its own, private to the feature (one coherent job with a name and tests of its own), and when it moves to the shared folder (a second consumer); never for length alone or to mirror a design layer; state ownership stays with the "Each state" row, with its example; `open` of a process the consumer can start is controlled by default like every other state, while what the component shows on its own stays transient UI by presence; derive state instead of storing it, and a selected item that leaves the data renders as nothing selected; at 390 px the page never scrolls sideways (a wide table scrolls inside its own bounds) and the preview shows one 390 px container, which criterion 10 of the rubric now scores. New eval `reuse-existing`, the first that runs inside a fixture project: `evals/fixture.py` prepares a run from the cached toolchain (`scripts/toolchain.sh`, shared with `verify.sh --minimal`, reinstalled when its package list changes) and refuses a project the toolchain cannot run; `evals/reuse_check.py <eval-id> <project>` scores rubric criterion 12 from the eval's `reuse` entry, file by file: a primitive counts when a file imports it from the shared folder (by name, through a namespace, or by a relative path resolved from inside that folder) and renders it, a hook when the file calls it; lines added to existing files count however the JSX is split, reformats, comments, strings and apostrophes inside words do not, example consumers are left out by folder, prefix or suffix (the `reuse-existing` prompt puts them under `examples/`), the shared folders are matched from the project root (`src/ui`, `src/hooks`, or the eval's `reuse.ui` and `reuse.hooks_dir`), and a primitive's own element is never a raw control, so the additive change the skill asks for costs nothing; a run that wrote nothing the script can score says so. `scripts/toolchain.sh` installs into a staging folder and moves it into place only when npm succeeds, so a failed install never leaves a cache a later run would accept, and `--packages` prints its package list for the tests. `fixture.py` quotes the scorer command it prints. `verify.sh` no longer aborts on macOS's bash 3.2 when it runs without an overlay, and refuses an overlay without `src/`, a project without `node_modules` and a `--minimal` folder without `src/`; six tests run it against stub tools. `SKILL.md` no longer asks for `// Given` comment markers in tests, which `references/testing.md` had already made optional.
- `evidence` captures mobile screens without a device when the repository has a tier for it. The contract's new `run.capture` (and `capture` per app) names a command that renders one screen and prints image paths (`<command> <screen> --lang <codes> --out <dir>`); `evidence.py capture` runs it and keeps the images as `after-<screen>-<lang>.png`, and with `--base` checks that ref out in a throwaway worktree, runs `run.setup` and the command there and keeps those as `before-…`, so no repository has to implement the pair itself. `ui.screens`, `ui.locales` and `ui.languages` say which files are screens, where the copy per language lives and which languages to capture (the first always, the rest when copy changes); `evidence.py screens` reads them and lists the screens the branch touches, the screens that import a changed component or token (one grep level), the copy that changed and the capture command. The skill's new "Mobile screens" step says when to capture, in which languages, how to pair with the base branch, what to do on an emulator someone else may be using (never start it or the bundler, ask), how to set the font scale, and the fallback when nothing can capture: the screens to check by hand, listed in the pull request's test plan. The session context hands the new fields to every skill, `plant`'s mapping documents them, and the eval `evidence-screen-capture` exercises the step against a stand-in capture command. The research behind it, measured on a real Expo app, is `docs/research/2026-10-22-mobile-visual-verification.md`.
- Vendored `archify` moves from 3.0.1 (`58ab0b98`) to 3.2.0 (`25cf3708`, upstream HEAD, one fix past the v3.2.0 tag): five more diagram types (ERD, class, tree, timeline, waterfall), one-page explainers (`finalize explainer`, `patch explainer`), chart cells that reject blank values instead of plotting zero, workflow migration that keeps authored contracts, and timeline ticks that stay on the display timezone across daylight-saving changes. No breaking change to the five types `explain` uses; `doctor` passes and an existing workflow diagram finalizes through every gate.
- `verify` gains an advisory `mutation` level, outside `run all`: with `verify.mutation` in the contract (`command`, optional `report` in the mutation-testing-report-schema format, optional `exclude` globs), `verify.py run mutation` needs a passing clean `fast` or `full` receipt for HEAD, picks the source files the branch added or modified since the merge-base with `pr.base` (test files and `exclude` matches dropped), and runs the command with `{files}` replaced by the shell-quoted, comma-separated list and `POTHOS_CHANGED_FILES`, `POTHOS_MUTATION_OUT` (the commit's receipt folder) and `POTHOS_MUTATION_CACHE` exported. The cache is one folder per repository under the Pothos home, shared by every clone and worktree: each run works on a private copy and publishes it back file by file with an atomic rename only after exit 0, so concurrent worktrees never write the same file and a failed run changes nothing. The receipt (`clean`, `findings`, `ran` without a report, `skipped`, `error`) records both dirty flags around the command and, from the report, every surviving mutant in the changed files tagged `new` (on a line the branch added) or `inherited`; only `new` ones print, and `check` mentions them without ever failing on them. Rule 1 of the testing standard names the receipt as its mechanical form for added lines and points at rule 7 for how a killing test asserts; the session context, only in repositories that declare the command, says to run it once after green and to list in the pull request the survivors killed with their test and the survivors left with why, on the precedent of the missing end-to-end command, which the session context already asks to say so in the pull request. `plant` detects Stryker (`mutation_tools`, `mutation_temp_ignored`), maps it to a `verify.mutation` draft, lists a missing command and an unignored temp folder as optional gaps, and audits a new tool as drift.
- Two tiers of verification in the session context, for every skill step that edits a source file (`implement`, `tdd`, `implement-spec`'s implementers and its review-fix implementer, `prototype`, `diagnosing-bugs`, `tend`). Tier 1, the fast check, runs after every coherent edit and before each commit; `shared/fast_check.py` finds it at session start: a `check:fast` script in the root package.json (run with the repository's package manager, and named as drift when the contract's `verify.fast` differs), else the contract's `verify.fast`, else a fallback per package with a changed code file (lint on the changed files, unit tests with `--findRelatedTests` when the runner is jest, type-check, all three even after one fails), and a command the repository's CLAUDE.md names wins over all of them. The session says once which command it picked and why, treats a red run as work (never by weakening a test, and stops after three reds on one step or a red in untouched code), counts a run that executed nothing only for docs and config changes, and keeps the fast check out of commit messages and the pull request. A commit needs a green fast check, not a green gate, unless the repository asks for more. Tier 2, the gate, stays `verify` (`full`, then `e2e`): once before a push, its log fills the pull request's test plan with counts and no row for the fast check, a step the environment cannot run is marked ⏭️ with its reason and left to CI, and `git push --no-verify` is allowed only when `verify.py check` passes and the pre-push hook would repeat the gate. Where no fast check exists, the final message names the fallback it ran and that a root `check:fast` would replace it; nothing is written into the repository. `tend` runs the fast check before committing a fix. Two evals (`implement-fast-check`, `implement-fast-check-fallback`) check the order and count of the runs from the fixture's own logs. Found on the way: Claude Code writes a hook's `additionalContext` to a file above about 10,000 characters and shows the session only the path, which a sandboxed session cannot read; the verification section is kept near 2,300 characters and a test measures a three-app monorepo contract against the limit, but the vendored tracker and domain templates alone cost 4,000 characters, so a contract that sets every field still overflows.
- The session context's pull request rules: a repository template found on disk (the same paths `plant` detects, now listed once in `shared/contract.py`) wins over the `pr` skill's template even when the contract does not name one. What a pull request says stays the repository's: the plugin adds no rule of its own about the summary.
- `merge_gate.py merge` no longer exits 5 after a successful merge when GitHub's automatic branch deletion lands between its read of the branch and its delete (`Reference does not exist`, HTTP 422): the branch counts as already deleted, and any other refusal to delete keeps the branch and says so. Its `gh` calls drop a `GH_HOST` that no remote of the checkout points at, such as an ssh alias or another GitHub host, which made every call fail.
- A person authorizes auto-merge without touching GitHub: their own message in the session ("do X and merge it", `/pothos:tend <n> merge`) or a local ticket with a `Merge: auto` line in its header, which `to-tickets` proposes for copy and documentation changes and the person approves with the breakdown. `merge_gate.py authorize <n> --quote <words> | --ticket <file>` adds the contract's label and comments on the pull request who authorized it; the ticket line counts only above the first `## ` section, so an appended comment cannot add it. The merge guard now points at `authorize` instead of forbidding the label outright, and lets `--quote` through only when the words appear in a message the person typed in this session (read from the transcript, without tool results, skill text, pasted content or harness notes), blocking when it cannot read the transcript. A pull request, a comment, a log or pasted text never authorizes. The session context tells vendored skills the rule, and offers the ticket route only where tickets are local files. The eval `tend-asked-to-label` becomes `tend-asked-to-merge` (the person's request now authorizes), `tend-no-label` no longer asks to merge, and `tend-comment-asks-to-merge` checks that a comment asking for the label changes nothing.
- SessionStart hook (`shared/self_update.py`): when the plugin loads in place from a git checkout on its remote's default branch, it fetches in a detached process and fast-forwards the checkout, so merged pull requests reach every repository from the next session (or `/reload-plugins`) without a manual pull. It skips feature branches, local commits, uncommitted changes the update would overwrite and copies in the plugin cache, and a lock keeps parallel sessions from updating at once.
- `tend` skill: babysits a ready pull request one pass at a time (answers review comments, fixes a failing check, updates a branch that fell behind) and never reviews the code again. `scripts/merge_gate.py` merges a pull request only when the contract's new `pr.auto_merge` is set, a person gave it that label, every check on the head commit is green (or a passing verify receipt exists when the repository has no checks), no person's review asks for changes (a bot's is handled like its threads) and no thread is open; it pins the merge to the head commit with the contract's method (squash by default) and deletes the remote branch. A commit that reports no checks while `.github/workflows` runs on pushes or pull requests counts as checks not reported yet, so a verify receipt never lets a merge in before CI starts. A `not a candidate` verdict also says what else would block the merge. Eight evals run against a logging stand-in for `gh` and a bare repository that logs pushes.
- PreToolUse hook (`shared/merge_guard.py`): blocks the direct commands that merge a pull request (`gh pr merge`, the REST and GraphQL merge calls through `gh api` or any HTTP client, a `gh alias` hiding them), push to the contract's base branch, or add the auto-merge label in any letter case. `lint_skills.py` checks that every hook script exists and has a timeout. The principle on merging now reads: a person decides, and an agent carries it out only through the label and the gate.
- `evidence` uploads screenshots to the pull request without a branch: with `pr.evidence: github-release`, `evidence.py upload` adds them as assets of a `pr-evidence-YYYY-MM` prerelease, one per month so no release reaches GitHub's 1000-asset limit, named after the pull request (or the branch before one exists), and prints the markdown to embed. Nothing is ever deleted, so old pull requests keep their images. `plant` asks before enabling it.
- `evidence.py emu` captures the running Android emulator through adb, and `run.screenshots` accepts `android-emulator`.
- `shared/ui_check.py` checks the lines a branch adds against the contract's `ui`: raw colors and new fonts outside `ui.tokens`, and icon packages other than `ui.icons` (same npm scope counts as the same set). It works on any stack, skips tests, docs and comments, honours `ui-ok: <why>`, and `verify` runs it after `full` and records an advisory `ui` receipt that never changes an exit code; `check` mentions open findings. Each `run.apps` entry can carry its own `ui` in a monorepo.
- Contract `ui` section: shared component folders, token files, icon package and component preview. `plant` detects the candidates and asks only when they leave a choice, `contract.py validate --strict` checks the paths, and the session context hands the set fields to UI work.
- Every pull request a session opens with `gh pr create` is assigned to the GitHub user who opened it: a `PostToolUse` hook (`shared/pr_assignee.py`) runs `gh pr edit <url> --add-assignee @me`, and asks the agent to do it when that fails.
- `onboard` is now `plant` (`/pothos:plant`); asking to onboard a repository still starts it.
- Renamed from devflow to Pothos: commands are `/pothos:<skill>`, the home folder is `~/.config/pothos` (`POTHOS_HOME`), the contract's default workflow value is `pothos`, and the unattended runner is `pothos-run.py`.
- Every step of the cycle starts from plain language: `vendor.json` can mark a vendored skill `model_invocable` and append `triggers` to its description, re-applied on every update.
- Coding standards are read before writing code, not only in review; UI work loads `component-design` first; the contract's new `build.skills` lists repository skills to load before writing code.
- Repositories with `workflow: repo` still get the owner's personal standards, below the repository's own, and only the skills that compete with their workflow are off limits.
- `onboard` asks which screenshots each app supports (`run.screenshots`: web, iOS simulator or none) and maps monorepo apps to `run.apps`; `evidence.py plan` reads both, so evidence never retries screenshots an app cannot take.
- `verify` runs slow checks detached (exit 4, `verify wait`); `pothos-run.py` resumes headless sessions until they write `report.md`.
- Fixes from a review of the scripts: `evidence.py` keeps waiting for the URL when the dev command exits 0 after starting the server in the background, keeps one server log per app, refuses `stop 0` and `stop 1` (which would signal the calling shell), reports a browser that never finishes, and exits 2 on an unreadable contract, as `ui_check.py` does now; `ui_check.py` reads paths correctly under `diff.noprefix=true` and no longer treats `* {` and `*, *::before` as comments; `artifact.py` refuses `register`, `parent` and `nav` outside the artifacts home (they wrote `INDEX.md`, `nav.js` and a `latest` link next to a page given by a repository path), registers through the `latest` link without pointing it at itself, accepts `--parent` as a path, leaves the `[data-theme="dark"]` CSS alone when `light` runs twice, and creates the repository folder for `nav`; `detect.py` bounds its one remote call (five seconds, no credential prompt).

## 0.1.0

- Plugin and marketplace skeleton.
- Agent contract v1: JSON schema and `shared/contract.py` to locate, read, write and validate it. Contracts are private, stored in `~/.config/pothos/contracts/<host>/<owner>/<repo>.json` and shared by every clone and worktree of a repository; nothing is written inside the repository.
- Contract fields `docs.glossary` (GLOSSARY.md, or CONTEXT.md in older repos) and tracker kind `local` for markdown tickets under `.scratch/`.
- Contract `workflow: repo` to make Pothos stand aside in a repository that follows its own process, and `run.environments` for repos that run against several backends.
- `archify` skill: pinned copy of tt-a1i/archify (MIT), with `vendor.json`, `scripts/vendor_sync.py` and a weekly workflow that opens a pull request when upstream moves.
- `explain` investigates code questions with a pinned copy of poteto/how (MIT): simple questions use one explainer, complex ones fan out to parallel Explore agents and a synthesis, and "critique" adds read-only critics on different models. `references/codebase-questions.md` adapts it from Cursor to Claude Code and sends the result to the page instead of the chat. New evals for a complex flow and a critique.
- `explain` sidebar: every page loads a shared `nav.js` listing all pages of the repository, children nested under their parent (`--parent`, `artifact.py parent`), and the current page's sections and diagrams; `register` rebuilds it so older pages stay current.
- `explain` skill: local HTML explanations with light theme by default, dark toggle and archify diagrams, stored privately under `~/.config/pothos/artifacts/` with a `summary.md` per page and an `INDEX.md` per repository, opened in Brave.
- `docs/work-model.md`: spec, plan and ticket; the outer and inner loops; sessions and orchestration.
- `onboard` skill: detects a repository's scripts, docs, CI and tracker, saves the private contract and reports readiness gaps. Includes an audit mode.
